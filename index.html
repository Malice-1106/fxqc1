研究对象与系统边界

SCENARIO & FUNCTION

旋翼数量不等于安全证据。真正需要回答的是：故障发生后，剩余能力是否足以完成受控着陆？

本文对象为EH216-S航空器、地面控制站、数据链与运行组织构成的系统。产品基础来自公开资料；内部电源拓扑、软件架构、控制律、失效率及试验报告未公开，文中的分区与监控架构均为课程提出的设计建议。

任务与功能

在经批准的运行条件与航线内完成载客起降、航迹跟踪、状态监控和异常处置；同时保障地面第三方。本文不将“无人驾驶”解释为无地面保障。

系统边界

纳入感知与导航、飞控与执行、推进与能源、机体与座舱、数据链与地面站、起降场和维护放行。外部接口包括气象、空域管理、供电设施、消防救援。

场景假设

课程分析选取白天、预先勘察航线、已知起降场、可用备降点场景；这些是研究假设，不是对该机型批准运行范围的转述。具体风、温度、能见度边界须来自飞行手册及批准文件。

顶层损失

L-A：乘员或地面人员伤亡；L-B：航空器与基础设施损坏；L-C：对其他航空器造成危险接近；L-D：事故或近失事件未被发现并反复发生。

课程映射：第77–78页提供安全分析与多维安全框架；第80–84页强调概念、系统、组件层级；第85–87页连接设计、测试与运行论证。本文沿此框架展开，而非仅罗列产品参数。[C1]

顶事件：失去完成受控着陆的能力

课程定性故障树：T = A ∨ B ∨ C ∨ (D ∧ E)。A为推进能力低于场景需求，B为机体关键结构损坏，C为共同资源/软件导致控制丧失，D为导航误导，E为完整性监控未及时阻断。最小割集为{A}、{B}、{C}、{D,E}。实际整机顶事件还需补充其他路径，本式只用于方法展示。

控制结构与不安全控制行为 · STPA

控制闭环：运行/充电与维护组织 → 地面站/能源任务管理 → 机载控制器 → 执行器与物理过程；状态、故障、控制权与环境反馈形成过程模型。下表分别检查四类不安全控制行为。

着陆区被占用时，未发出中止下降指令。

过程模型缺陷：地面占用状态迟到，飞控过程模型仍显示“可降落”。

安全约束：SC01：占用状态失效或超过时效时，不得继续依赖旧授权下降。

设计与验证：采用空地统一状态机，验证占用信息更新、过期检测与机载兜底。

定位完整性不足时仍提供继续航线指令。

过程模型缺陷：系统将“数值有输出”误认为“位置可信”。

安全约束：SC02：导航完整性低于任务需求时，不得继续执行依赖该精度的航段。

设计与验证：将定位健康度、控制余量和备降可达性联合输入降级决策。

航线切换指令在飞行阶段不适合的时刻生效。

过程模型缺陷：地面发令时机与机载实际阶段不同步。

安全约束：SC03：切换前核验阶段、控制权、航线版本与生效时刻。

设计与验证：延迟、失序、重复与重连试验覆盖所有控制权交接。

故障后长时间保持悬停，消耗备降能量。

过程模型缺陷：调度系统等待链路恢复，忽略电量持续下降。

安全约束：SC04：异常等待须有能源边界，达到触发条件应执行预先验证的安全策略。

设计与验证：将剩余能量置信下界与可达备降点作为退出判据。

安全架构与多维防护

ARCHITECTURE / DESIGN

以下是候选架构，尚未被实现或验证。每层防护必须说明独立性、检测覆盖、响应时间和故障后能力；架构图本身不能形成安全结论。

任务层

航线与备降规划、放行条件、能源余量

独立监控层

完整性监督、模式一致性、故障与越界监测

执行层

飞控重构、推进分配、分区供电与隔离

保护层

结构吸能、热烟隔离、撤离和地面救援

功能安全

从故障传播路径推导隔离与监测要求。投票冗余必须审查公共电源、时钟、通信总线和软件共因；不能仅凭三套计算机认定安全。

预期功能安全

城市多径、低对比障碍、阵风与异常起降区可能使正常工作的传感器与算法能力不足。用触发条件、已知不安全场景及边界探索组织测试。

行为与人因

定义地面调度、乘客紧急请求与机载自治的控制权。对错误授权、告警过载及乘客误操作分别设计防护；乘客不承担飞行员级接管义务。

信息安全与电磁兼容

资产包括航线、位置、控制指令与软件。TARA链为未授权访问—错误航线/指令—越界风险；采用认证、最小权限、签名和时效检查，并验证拒绝服务与电磁干扰下的降级。

机械、电气与化学

审查旋翼破坏、疲劳、线束磨损、绝缘失效与热传播。物理分区必须包含热、碎片与液体侵入路径，避免空间相邻使逻辑独立失效。

安全文化与供应链

危害日志由系统安全负责人维护；供应商提交接口、失效模式与版本证据；试验负责人对未闭合条目设置停止放行条件，独立评审人审查残余风险接受依据。

时间与能力的共同约束
t检测 + t决策 + t执行 < t危险发展允许；同时，故障后可用功率 ≥ 着陆轨迹需求，剩余可用能量 ≥ 着陆能量 + 经论证的裕量。各量必须按最不利场景测定，不在本分析中虚构统一毫秒数或安全系数。

让每条需求有验证出口

REQUIREMENTS / V&V

下表形成“危害—需求—分配—测试—判据”双向追溯。所有需求为候选要求，所有试验为计划，状态统一为未执行；冻结数值前须先获得机型级安全分配、接口、环境边界和批准依据。需求也应反向追溯至危害日志，变更后重新评估。

需求危害分配对象候选安全需求测试验证方法通过判据 / 待定项
R01H01推进/能源候选：单一推进单元故障后，目标场景内的剩余推力与力矩应支持已定义的受控着陆轨迹。T01动力台架、SIL/HIL与递进飞行试验全质量/重心/环境包线下轨迹和控制裕度均满足冻结要求；数值待气动与动力模型确定。
R02H02导航/决策候选：完整性失效须被检测并在越出安全走廊前完成降级响应。T02城市峡谷、多径、欺骗场景仿真与封闭场地试验测得检测+决策+执行时间小于场景允许时间；两者阈值待航线与动态模型分配。
R03H03热防护/座舱候选：单电芯热事件不应在安全着陆和撤离所需时间内导致关键多路系统丧失或座舱危险暴露。T03代表性安装下热传播、烟气与隔离试验关键功能与乘员暴露满足项目限值；时间及浓度阈值需专项论证。
R04H04空地交互候选：落地区占用信息无效时阻止继续依赖旧授权执行着陆，并保持可行退出路径。T04人在环/地面站联试与侵入场景测试错误授权不得导致危险接地；退出轨迹与能源满足场景约束。
R05H05数据链/状态机候选：机地控制权须唯一；丢链、重连和延迟不得触发重复或过期动作。T05断链、乱序、重放与模式转换故障注入所有定义的时序路径均满足状态机不变量，记录被拒指令与模式反馈。
R06H06气象/运行候选：超出经确认的风雨边界前阻止放行或触发安全退出。T06气象重放、阵风仿真与分级环境验证边界内可控，边界外能识别退出；数值以批准数据为准。
R07H07结构/人因候选：定义的迫降冲击与失电后仍保有撤离路径。T07结构冲击、约束载荷与失电撤离演练满足项目伤害判据及撤离时间目标；参与者差异与组合事件须覆盖。
R08H08组织/构型候选：安全相关更新与维修应可追溯至受影响需求、测试和放行责任人。T08配置审计、错误版本注入与回滚演练无法确认构型一致性时不得放行；回归范围有双向追溯记录。

分层验证与停止条件

组件与模型

审查模型假设和接口；对传感器、执行器与保护机制做边界和故障注入测试。保留输入、版本、仪器校准和失败记录。模型未经相关性确认，不外推整机结论。

系统集成与整机

SIL/HIL覆盖延迟、失序、复位、潜伏故障与共因；随后按风险分级进行地面和递进飞行验证。关键安全机制失效、场景边界未知或证据缺失时停止进入下一阶段。

运行与持续适航

确认放行检查、备降、撤离和救援流程。监控近失事件、性能退化与维护差错；重大变更触发危害重评估和回归验证，不将“未出事故”当作证明。

安全论证与闭合条件

SAFETY CASE / LIFECYCLE
G0 · 待证明的顶层主张
在明确定义并遵守的运行条件内，所分析系统的风险经充分控制，且支持任务的安全完成与异常情况下的受控退出。此处为论证结构，不是已经成立的产品安全结论。

G1 · 设计充分

用FHA、FMEA、FTA、STPA与CCA证明危害已被识别，需求分配与独立性假设完整；所需证据为设计审查、模型与计算、接口和构型记录。

G2 · 实现与验证充分

用组件、集成、整机和最不利场景测试证明需求被满足；所需证据为可重放数据、测试报告、失败处置和独立验证记录。

G3 · 运行约束有效

用放行、维护、人员培训、应急与消防演练证明风险控制在运行中可持续；所需证据为演练结果、健康趋势与事件闭环。

反驳项与接受责任

追问共同资源、未知环境、估计误差和证据代表性。未闭合高风险项由项目责任主体与独立安全评审处理；本课程网站不执行实际风险接受。

标准与方法如何使用
课程第81–83页介绍汽车ISO 26262、ISO 21448、ISO/SAE 21434以及航空ARP4754/ARP4761、DO-178/DO-254等方法体系。本文借鉴其分析思路，不把道路车辆ASIL直接等同于航空研制保证等级，也不以“10⁻⁹”统一替代具体型号的分类、目标与符合性要求。航空器适用审定基础及版本需按主管机构和项目文件确认。[C1、C2] EH216-S专用条件作为识别该系统审定范围的历史公开依据，具体批准限制仍以现行项目文件为准。[P2]
分析局限与下一步证据
本研究没有型号内部设计、失效率与批准运行手册；危害等级和矩阵为课程初筛。未开展实际台架或飞行试验，因此所有残余风险均为“待验证”，不能据此宣称产品不安全或完成适航符合性。下一步应取得接口与构型文件，冻结ODC、时序和能力目标，补充试验数据，再审查每项残余风险。

优先关闭共因故障、低高度单故障可控性、机地控制权和热事件后果四条证据链。公开产品构型和取得证书的事实，不能替代本分析提出的具体安全要求的验证。
